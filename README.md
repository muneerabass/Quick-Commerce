# Zipp — quick-commerce app (Phase 1)

A polished React Native + TypeScript quick-commerce front end: splash, auth, home,
categories, search, product details, cart and profile. Everything runs on local mock data
behind service-shaped seams, so Phase 2 can swap in a real backend without touching the UI.

## Running it

```bash
npm install
npx expo start
```

Then press `i` for the iOS simulator or `a` for an Android emulator.

The `ios/` directory is generated by `npx expo prebuild`. To rebuild natively:

```bash
npx expo run:ios
```

If CocoaPods fails with a `unicode_normalize` error, run it with an explicit locale:
`LANG=en_US.UTF-8 pod install` from `ios/`.

## Architecture

```
src/
  theme/        design tokens — colors, spacing, typography, shadows, responsive layout
  types/        domain models (Product, Category, CartItem, User, Address)
  data/         mock catalogue: images, categories, products, home sections
  services/     storage (AsyncStorage wrapper) and authService (mocked API)
  context/      AuthContext and CartContext — Context + useReducer
  hooks/        useCatalog, useDebouncedValue, useRecentSearches
  components/   reusable UI, all theme-driven
  navigation/   Root → (Splash | Auth | Main) → Tabs + pushed stack screens
  screens/      one folder per feature area
```

### Where the backend plugs in (Phase 2)

Every network-shaped boundary is already async and already returns the final view model:

| Seam | File | Replaces |
| --- | --- | --- |
| Auth | `src/services/authService.ts` | `POST /auth/otp/request`, `/verify`, `/signup` |
| Home feed | `src/hooks/useCatalog.ts` | `GET /home` |
| Catalogue | `src/data/products.ts` | `GET /products`, `GET /search` |
| Categories | `src/data/categories.ts` | `GET /categories` |
| Cart | `src/context/CartContext.tsx` | server cart sync |

`requestOtp` / `verifyOtp` already exist in `authService` and are unused by design — the OTP
screen slots between "Continue" and "signed in" without reshaping `AuthContext`.

## Notes

- **State**: Context + `useReducer`. No Redux — the state here does not justify it.
- **Cart** persists to AsyncStorage and is cleared on logout.
- **Images** are remote photographs; each URL was fetched and visually checked against the
  product it is filed under. `ProductImage` falls back to an illustrated emoji tile on load
  failure, so the grid never shows an empty box offline.
- **Animations** use Reanimated on the UI thread: press-scale, add-to-cart width spring,
  cart badge pop, tab indicator, staggered list entrances.
- **Checkout is intentionally a stub** — it shows a "coming soon" dialog and keeps the cart.
